# Java S1854: entry into colon switch groups

A traditional Java `switch` can enter any matching `case:` group directly.
It can also enter the next group by falling through the previous one. The
native liveness graph used only the previous group's exits after the first
group. A `return` or `break` could disconnect later groups, and a write in an
earlier group could hide a read on direct entry to a later group.

For example, Apache Commons Lang's
[FastDatePrinter.java at the tested revision](https://github.com/apache/commons-lang/blob/105a350b154eac7c3f3a6bac94ec2cfb0fbe232b/src/main/java/org/apache/commons/lang3/time/FastDatePrinter.java#L190)
stores month and weekday names before a switch. Later groups read those
arrays. Hoonarqube reported five of the initializations as dead; Sonar did
not. The graph now connects each colon group to the selector and keeps its
fallthrough predecessors.

## Controlled reproduction

The [committed Java fixture](../../crates/hoonarqube-java/tests/fixtures/SwitchEntry.java)
contains direct entry after a return, direct entry after a break, direct entry
with ordinary fallthrough, genuine dead writes, and an arrow switch.
The old CLI reports three live initializers at lines 3, 13, and 28.
Sonar and the fixed CLI instead agree on the two genuine dead stores at
`40:18–28` and `43:22–32`. The regression test
`colon_switch_dispatches_to_every_case_group` checks these precise ranges.

## Replay

Build the before and after Hoonarqube CLIs with
`cargo build --locked -p hoonarqube-cli` in separate worktrees and target
directories. Export only regular `.java` files under each listed source scope
from the pinned Git revision. Run each CLI on that scope with
`hoonarqube analyze --json --profile sonar-parity <scope>`.

For the additional Sonar comparison, use read-only Java sources and a fresh
project per scope. Set `sonar.sources` to the listed directory,
`sonar.inclusions=**/*.java`, `sonar.java.source=25`, and
`sonar.java.binaries` to an empty directory. Do not load upstream project
settings. Read back project history, indexed file paths, the active S1854
rule, and all pages of that rule's findings. Compare S1854 by path and
UTF-16 range once file scopes and source bytes match. The scan images were
`sonarqube@sha256:c0f1160bccfa435db4168c2d7df69af3c3ea7bfeb87395613014048fb33a68c1`
and
`sonarsource/sonar-scanner-cli@sha256:23ca0f137965d9dff2198074043fd48d386280bc5d0ccac8c8349cea4cf096a9`.
