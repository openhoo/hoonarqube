# Public C# comparison with SonarQube Community Build

November 20, 2026. SonarScanner for .NET compiled and scanned four pinned
public C# projects. SonarQube finished all four compute tasks and indexed
157 of the 161 compiled files. Hoonarqube reported all 161 files with its
C# compiler context marked `missing`.

The [qualification receipt](public-csharp-pilot-qualification-20261120.json)
contains the Git commit and tree, source root, compiler symbols, every
input and raw source SHA-256, and compute and analysis IDs for each project.

Stateless compiled four tracked `*.Designer.cs` files marked
`<auto-generated>`. SonarQube's file index omitted those four files.
Hoonarqube reported them. The receipt lists the exact omitted paths.

The findings columns count ordinary primary rule findings on identical
file scopes. They include shared rules with matching declared parameters
and exclude documented native implementation gaps. An exact match uses
the rule, project-relative file and full UTF-16 range. These observations
compare Hoonarqube's source scan against a compiled Community Build
reference. They do not qualify compiler-context parity, Enterprise
sensors, detector equivalence, secondary locations, or quick fixes.

## What ran

- .NET SDK **10.0.111**, with the installed **10.0.11** .NET 10 reference
  assemblies, and **SonarScanner for .NET 11.2.1** using **OpenJDK 21.0.13.1**.
  SonarQube **Community Build 26.9.0.129388** supplied C# plugin
  **10.33 (build 1635)** with the built-in Sonar way profile. The receipt
  gives the server image, scanner package and DLL, compiler, and analyzer
  digests.
- The harness fetched Git objects and copied only the selected tracked
  `.cs` blobs into isolated directories. It wrote minimal MSBuild projects
  with explicit compile items, project-specific symbols and local reference
  assemblies. Each project built before the scanner ran. The scanner then
  ran `begin`, `dotnet msbuild Pilot.csproj -t:Rebuild` and `end`. The rebuild
  logs show the pinned Sonar C# Roslyn assembly. No upstream project file,
  target, script, generator, or package restore ran.
- All **161** staged source files were byte exact against the pinned Git
  blobs. An independent readback fetched all **157** indexed sources from
  SonarQube and confirmed the stored SHA-256 values. The raw endpoint
  returned the same text after it removed BOMs where present, normalized
  CRLF where present, and added one final LF in this capture. The raw API
  responses and the staged byte-exact inputs are separate evidence.

  `9084eeca7eb9350f028fa9a791b1f0f0ca395968`. The verified-at-start
  `main` commit `e43dc65805fdba7c4cd27c1cbfc6f285c717f87d` had the same
  Git tree, `5d9ccd5cc837d3fb2105172bcbeccb7cfc0866bc`. The executable SHA-256
  was `e719261d0fe6db1f53d362da0ec55b3da152d4a9ec7034474b56018124552021`.
  This evidence branch was opened from the first public corpus

## Replay the evidence

Use Python 3.11 or newer, Git, and a fresh private directory outside the
repository. The public check fetches the exact commit and verifies its tree
and every C# blob against the receipt. It also reconstructs the observed
raw endpoint normalization from the Git bytes and checks the published
hashes. It does not compile or contact a SonarQube instance.

```sh
umask 077
oracle=tools/oracle
state=$(mktemp -d)
python3 "$oracle/public_csharp_pilot.py" --state "$state" fetch
python3 "$oracle/public_csharp_pilot.py" --state "$state" verify
python3 "$oracle/public_csharp_pilot.py" --state "$state" stage --sdk "$sdk"
```

`sdk` is the directory containing `dotnet` and the installed reference
assemblies. Staging is optional for the source audit and runs no compiler.
The generated project SHA-256 records the historical file, including
absolute paths to the reference assemblies. Compare source hashes across
machines. Compute and analysis IDs are specific to each run.

With the original private Git/stage/capture directories, the active profile
snapshot, and the native catalog from the pilot, the following independently
recomputes the finding counts from the retained reports and checks the
execution records. This is the command used to audit the published totals:

```sh
python3 "$oracle/public_csharp_pilot.py" --state "$historical" audit \
  --effective "$effective" --native-catalog "$native_catalog"
```

The four public fetches, source verification, isolated project staging,
historical audit, tool hash check, and live compute and raw source readback
were rerun for this evidence. With the original SDK path, all four freshly
staged project files also matched the captured project files byte for byte.
The portable capture wrapper below was assembled from the verified live
commands; it was not used to start another four scans during packaging.

### Repeat the live scan

Use the exact SDK installation, local scanner package and extracted
`SonarScanner.MSBuild.dll`, Java executable, and native binary recorded in
the receipt. The native and .NET host hashes are platform specific. Keep
at least **5 GiB** free and run with a trusted SDK in the private staging
directory. The wrapper runs projects sequentially.

Set up an owned reference using the pinned image and internal network in the
[first corpus runbook](public-corpus-20261120.md). The host must be able to
reach that private container address directly. Use a disposable token in
a private file. Set `effective` to the active profile snapshot from that same
reference instance, for example the `profiles/effective.json` written after
the first corpus runbook's live pilot. Both commits listed under native
provenance must be present in the local Git repository for findings replay.

```sh
python3 "$oracle/public_csharp_pilot_capture.py" --state "$state" check-tools \
  --sdk "$sdk" --scanner-package "$package" --scanner-dll "$scanner" \
  --java "$java" --binary "$native"

python3 "$oracle/public_csharp_pilot_capture.py" --state "$state" capture \
  --sdk "$sdk" --scanner-package "$package" --scanner-dll "$scanner" \
  --java "$java" --binary "$native" --effective "$effective" \
  --reference-state "$reference_state" --reference-container "$container" \
  --reference-network "$network" --token-file "$token_file" \
  --project-prefix public-csharp-replay
```

Use a unique project prefix on subsequent runs. To recheck the historical
raw source while its original reference is still available, use the
read-only command below. The token and all raw captures remain private.

```sh
python3 "$oracle/public_csharp_pilot_capture.py" --state "$historical" readback \
  --reference-state "$reference_state" --reference-container "$container" \
  --reference-network "$network" --token-file "$token_file"
```
